# ResumeAI4u design research

## Research summary

The product's primary journeys are: learn what ResumeAI4u does and try the estimator; register/sign in; upload or paste a resume and a target job description; review ATS analysis and edit/copy suggestions; revisit history; and choose a paid plan. The current landing page is long, dark, and visually busy. The optimizer starts with two equal-weight text panels, so the next step is not obvious. Pricing and auth screens use a separate dark visual language, while the dashboard puts transient toast feedback where persistent field and result context would help.

Two directions were compared:

1. **Dark analytics console:** persistent rail, score widgets, dense cards, and a saturated accent. It suits repeated monitoring, but adds navigation weight to a task-driven product and competes with the resume content.
2. **Editorial workspace (selected):** warm white surfaces, near-black typography, thin neutral borders, one restrained blue action color, and a clear guided optimization flow. It preserves ResumeAI4u's black-and-white identity, emphasizes writing and review, and can reuse the existing React/Tailwind stack without adding component dependencies.

| Direction | Clarity | Usability | Accessibility potential | Implementation cost | Identity fit |
|---|---|---|---|---|---|
| Dark analytics console | Medium: many metrics compete with the resume task | Medium: good for returning users who monitor activity | Medium: dense panels and saturated status colors need extra contrast work | High: persistent rail and dashboard composition would replace much of the current layout | Low: adds a heavy, colorful visual language |
| Editorial workspace | High: one primary task with ordered stages | High: upload/paste, analyze, and review stay in sequence | High: readable surfaces, labels, focus states, and stacked narrow layout are straightforward | Low to medium: uses existing routes, React, Tailwind, and Lucide | High: retains the black-and-white identity with restrained blue |

The selected direction uses a compact public navigation, one clear landing CTA, a centered content column, numbered workflow stages, accessible file-selection controls, visible analysis progress, persistent inline errors/results, and a side panel for score/actions on wide screens. On narrow screens, panels stack and navigation/actions wrap. Focus, hover, selected, disabled, loading, empty, success, and error states use text and shape in addition to color.

## Compact design specification

- **Identity:** minimalist black/white editorial canvas; warm-white page background; white work surfaces; ink-black headings; quiet stone-gray borders and text; one focused blue accent; semantic green/amber/red only for state.
- **Typography:** existing system/Inter-first sans stack; large, concise page headings; readable 14â€“16 px body and form text; uppercase micro-labels used sparingly.
- **Spacing and surfaces:** 8 px spacing rhythm; 12â€“16 px surface radii; light borders instead of glass, glow, and gradient stacks; keep result content readable and calm.
- **Navigation:** public header with product, pricing, and one primary account/workspace action; dashboard header with workspace identity, two task tabs, history, and account action.
- **Workflow:** step labels for target role/job, resume, and analysis; visible supported formats and 10 MB limit; preserve paste alternative; run action disabled only while busy or invalid; after success, show score and editable suggestions with review guidance.
- **States:** inline validation, upload filename/progress/success, analysis progress with live status, explicit API failure/retry, empty history instructions, selected tab, disabled/busy action, and payment result feedback.
- **Responsive behavior:** mobile-first; stack dashboard work panels below 1024 px and use two columns above that; show three pricing cards from 768 px; constrain reading width around 72 rem; preserve touch-friendly spacing and avoid horizontal scrolling.
- **Accessibility:** semantic headings, labels associated with inputs, keyboard-operable controls, visible focus, `aria-live` for async progress and results, non-color-only status, reduced motion, and adequately sized icon buttons.
- **Implementation:** React 18, Tailwind 3, Lucide, and existing app components only; no new UI dependency or framework migration.
